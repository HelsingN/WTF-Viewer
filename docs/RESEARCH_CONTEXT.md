# Исследовательский контекст и макроанализ

Этап 5 выводит данные выбранного пакета поверх reader этапа 4. Открытие материалов использует датированные артефакты и реестр пакета. Отдельный локальный пересчёт использует результат на указанную дату оценки.

## Расчёты и покрытие

- Поддержаны недельные артефакты в основном наборе, архиве и предложениях из PR, а также сохранённые событийные пересчёты. Каждый показывает свой срез, интервал, факторы R1–R7 и доступные поля покрытия. События без записанного статуса включения и отсутствующие наблюдения показываются как `UNKNOWN`.
- В наблюдениях видны источник, класс, доступность на дату среза и срок действия. Исторические решения из основного реестра фильтруются по времени расчёта. Для предложенных артефактов связь с реестром иной ревизии остаётся `UNKNOWN`.
- Открытые проверки берутся из `unresolved` и последних статусов `PENDING_REVIEW` / `EARLY_WARNING` в реестре. Доступны дата, причина, источники и следующее действие, когда оно зафиксировано. Приложения `weekly_coverage` показывают комплектность, актуальность и пробелы по блокам.
- Исторический портфель макрособытий, поздние события без ранга, сравнение по каналам, перекрытия и сценарии отображаются из своих артефактов. Порядковые ранги сохраняются в исходном виде. Интервал Macro Pain подписан как значение отдельного артефакта.

## Данные workflow

Запись отчёта в `research/report-index.json` может содержать необязательный объект `workflow` с отдельными ключами `ci`, `review`, `merge`. Для каждого наблюдения указываются `status`, `observed_at` (ISO 8601 с поясом) и `inspected_sha` (40 знаков). Статус сопоставляется с `source_commit` отчёта. Наблюдение для другой ревизии показывается с собственным временем и SHA, а состояние для ревизии отчёта остаётся `UNKNOWN`. Отсутствующие и неполные наблюдения также дают `UNKNOWN`. Индекс и идентификатор исходного PR сохраняют своё происхождение независимо от workflow.
