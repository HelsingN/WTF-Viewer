# Пакеты исследований v1.2

Viewer открывается на пакете, доставленном со сборкой сайта. Он содержит точную ревизию GitHub WTF-Viewer, отчёты с полными текстами, приложения, источники, реестр событий и материалы Challenger. Встроенный пакет зафиксирован на [коммите данных](https://github.com/HelsingN/WTF-Viewer/commit/ec7de3b7f5f18bdaa87a9311ae4005a32ec18cc8). В нём 196 файлов, 19 основных ежедневных и 8 основных еженедельных отчётов, 3 отчёта из незавершённых PR, 1 архивный еженедельный отчёт и отдельная запись о неполном дне. В реестре 47 событий.

Снимок Challenger от 11 ноября имеет статусы `PARTIAL` и `REQUIRES_HUMAN_REVIEW`. Снимок от 18 ноября хранится вместе с материалами PR #231. Для каждого источника сохранены собственные даты и ссылки.

## Обновить данные вручную

Из клона [WTF-Viewer](https://github.com/HelsingN/WTF-Viewer) с Node.js 22.13+ и установленными зависимостями подготовьте JSON по полному SHA.

```sh
git fetch origin develop
git rev-parse origin/develop
npm run research:package -- <полный_SHA_из_предыдущей_команды> refs/heads/develop outputs/research-package.json
```

Сборщик читает только Git-объекты выбранного коммита. Он проверяет, что commit находится в полученной истории ветки, и сверяет байты файлов. Незакоммиченные изменения рабочего дерева на результат не влияют. Для каждого файла в `research/` в пакет входят путь, размер и SHA-256. Индекс отчётов связывает документы с периодом и исходным статусом, а manifest переноса сохраняет историю из AI_CapEx_Reversal. Дополнительные приложения нового отчёта можно перечислить через `attachments` в его записи в `research/report-index.json`.

В Viewer нажмите **«Выбрать пакет JSON»** и проверьте коммит, состав, версии и пробелы в предпросмотре. **«Открыть локальный набор»** применяет пакет в текущем браузере. Выбор обычно восстанавливается через IndexedDB после перезагрузки. Когда хранилище недоступно, выбор действует до перезагрузки и интерфейс просит выбрать файл заново. Кнопка **«Сбросить локальный выбор»** возвращает встроенный пакет.

Повторный выбор того же содержимого на том же SHA проходит без изменений. Пакет с более ранним временем коммита, повреждёнными байтами, несовместимыми версиями, удалённым событием либо переписанным ревью отклоняется. Хеши проверяют согласованность содержимого. Связь с историей Git сборщик подтверждает при сборке, а Viewer после импорта показывает ссылку на указанный commit и маркирует набор как локальный. В Viewer доступна ручная выгрузка пакета в JSON и списков в CSV.

## Встроенный пакет и исторический стол

Для обновления пакета следующей сборки сайта передайте сборщику путь `public/research-package.json.gz` вместо `outputs/research-package.json` и закоммитьте полученный файл. Отдельная публикация сайта доставит этот пакет. Ручной импорт обновляет только локальный выбор.

Ссылка **«Исторический рабочий стол»** открывает прежнюю версию интерфейса по пути `/legacy`. Сохранённые там записи D1 и её авторизация остаются доступны по существующим правилам. Новый reader работает отдельно с файлами выбранного пакета.

В текущем reader доступны списки из индекса, просмотр исходного Markdown и загрузка связанных файлов. Форматированный Markdown, развёрнутое отображение источников и полная приёмка reader относятся к этапу 4. Пересчёт Challenger по структурированным входам относится к этапу 3.

## Проверка

`npm run check:research-package` сверяет встроенный файл с повторной сборкой по commit SHA и проверяет контракты импорта. Для повторения проверки в новом клоне нужны обе ревизии и ref `origin/develop`.

Два пакета для браузерного сценария собираются из `c79e9789da299c578e76cc11a7494e3ecf127b79` и `ec7de3b7f5f18bdaa87a9311ae4005a32ec18cc8`. У первой и второй ревизии один и тот же реестр, поэтому смена SHA должна оставить 47 событий. Начните браузерный сценарий со сборки с более ранним пакетом `c79e978`, импортируйте `ec7de3b`, затем перезагрузите страницу и повторите импорт. Для отрицательной проверки удалите `files["research/report-index.json"]` из копии JSON, измените контрольную сумму или идентификатор модели. Активная версия должна остаться доступной после каждой ошибки.
