# WTF Viewer — согласование назначения первой версии (v1.2)
Редакция: 21 ноября 2026, Asia/Jerusalem. Статус: DOCUMENTED; перенос данных, разработка и приёмка не выполнены.

## 1.1. Назначение

Первая версия — просмотр исследований Challenger, ежедневных/еженедельных отчётов и их рабочих статусов из GitHub WTF-Viewer, плюс детерминированный пересчёт по принятым структурированным входам. Подготовка текста отчётов, самостоятельная квалификация событий, рекомендации и решения, редактор заметок, сохранение личной работы и запись в GitHub из приложения — последующее расширение с авторизацией и правами.

«Только просмотр» означает отсутствие записи в общие источники. Локальные фильтры, выбор пакета и расчёт в памяти браузера допустимы. Рабочие статусы показываются из импортированного источника; первая версия не создаёт серверный журнал ручных решений.

В существующем прототипе уже есть ChatGPT identity, D1 и закрытый Sites-доступ. Не отключать и не обходить их. Будущее добавление авторизации означает проверку редакторских прав для новых write-функций, а не требование открыть текущий сайт всем. Новая миграция заметок/D1 не является предварительным условием первой версии; существующие записи не удалять.

## 1.2. Источник, перенос и обновление

**Решение владельца:** после проверенного переноса основной источник исследований Challenger и ежедневных/еженедельных отчётов — **GitHub HelsingN/WTF-Viewer**. AI_CapEx_Reversal остаётся архивом исходной истории перенесённой области.

Это целевая смена источника, ещё не выполненная миграция. Сейчас исходные материалы находятся в AI_CapEx_Reversal; встроенный seed и карточки отчётов в Viewer не подтверждают полный перенос текстов/приложений.

- Переносится связный набор: модель/политика/контракты, реестр и reviews, входные наблюдения, источники и eligibility, расчётные артефакты, daily/weekly тексты и приложения, индексы/манифесты полноты, связи и незавершённый контекст.
- На выбранном source SHA составляется manifest: исходные repository/ref/path/blob SHA, target path/hash, тип, дата/cutoff и сохранённый canonical ID. Основной перенос из main; proposed/unmerged материалы отдельно помечаются по собственным SHA.
- Содержимое исходных материалов переносится без скрытого переписывания; старые пути/ссылки сохраняются в manifest, Viewer разрешает внутренние ссылки через mapping. Новые корректировки после перехода ведутся в WTF-Viewer с историей.
- Сверяются полнота, байтовые hashes, ID, связи и документы. Только после сверки фиксируется cutover: источник, дата и точный target commit с полным набором. До него интерфейс показывает, откуда реально прочитаны записи.
- Архив исходной истории означает сохранение и явную отметку происхождения, не удаление репозитория/веток и не автоматическое изменение его GitHub archive setting. Другие области AI_CapEx_Reversal не переносятся по умолчанию.
- Старые отчётные автоматизации учитываются при плане перехода, чтобы не создавать две независимые активные версии. Настройки, расписания и исходный репозиторий сейчас не меняются.

Первая версия использует ручной цикл: материал обновляется в GitHub WTF-Viewer → из конкретного commit собирается проверенный пакет с полными текстами/данными → пакет вручную импортируется в Viewer. Это синхронизация по версии с возможностью повторного импорта, а не live API. Показать source commit/cutoff, дату получения и доступность блоков. Повторный тот же пакет — no-op, ошибка сохраняет прежний набор.

Обратное направление на первом этапе: расчёт можно скачать и вручную добавить в GitHub обычным процессом владельца. Сайт сам не создаёт commits/PR и не объявляет локальный результат опубликованным.

Далее — автоматическая сборка пакетов/обновление публикации, явный read-only Refresh и затем разрешённые write-сценарии с авторизацией. Публикация кода сайта и обновление исследовательских данных — разные процессы.

## 1.3. Пересчёт Challenger

Первая версия должна считать по запросу: кнопка **«Пересчитать Challenger»**, а также повторное вычисление при обновлении страницы по загруженному пакету. Реализация — чистое вычислительное ядро в браузере, совместимое с зафиксированным Python-эталоном, без изменения модели или автоматической записи в GitHub.

Вход — versioned reviewed snapshot, cohort/policy, event ledger и явный evaluation_as_of; произвольные Markdown-отчёты не являются готовыми числами. Извлечение и экономическая квалификация данных автоматически не выполняются. При отсутствии валидного входа показать причину невозможности расчёта; при допустимой неполноте — честный интервал/UNKNOWN по действующим правилам.

- Один input hash + model/code version + policy version + evaluation_as_of задаёт один вычислительный результат. Повторный refresh использует кэш либо повторяет чистую функцию, без нового экономического события, отчёта или дублирующего артефакта.
- Refresh загружает доступный приложению пакет/локально выбранный набор. Он не означает live-загрузку новых публикаций. Время страницы не подменяет даты источников и расчёта.
- По умолчанию evaluation_as_of берётся из пакета. Новый as_of выбирается явно; действие «на текущую дату» не снимает expiry, freshness и отсутствующие наблюдения. Результат содержит входной hash, versions, as_of, evaluated_at и причины исключений.
- Локальный расчёт помечен LOCAL/UNPUBLISHED и отделён от последнего опубликованного результата. Экспорт не равен публикации или утверждению исследования.
- Проверить численную совместимость с Python: decimal-арифметика и округление, веса/caps/decay, даты/PIT/expiry, неполнота, policy qualification, исключения и контрольные наборы. Фиксированный one-off скрипт с датой ноября не является универсальным API.
- Python-код не объявляется исполняемым в существующем Worker. Перенос арифметики для браузера — техническая реализация той же версии модели; при расхождении с эталоном выпуск блокируется.

## 1.4. Отчёты, исследования, статусы и заметки

Обязательны списки daily/weekly, полный просмотр материалов и источников, поиск/фильтры, история расчётов, отображение статуса и происхождения каждой записи, ссылки на файл и версию в GitHub WTF-Viewer. Отдельно показывать наличие текста, комплектность источников, исследовательскую квалификацию и статус рабочего процесса.

Файлы Markdown и JSON — основной сохраняемый результат, а не только карточки с числом записей. Интерфейс строит список из manifest выбранного пакета. Сайтовые заметки и пользовательские черновики не блокируют первую версию. Подготовка нового отчёта, изменение квалификации/рабочих статусов из сайта и редакторские решения — после авторизации и прав.
